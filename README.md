## 区域选错，后面全是麻烦

镇江和宿迁都是 BGP 线路，电信、联通、移动用户接进来延迟都比较平均，这是开 MC 服最省心的选择。镇江走 NAT 网络，多个用户共用一个公网 IP，需要自己做端口映射，面板提供 15 个端口。

宁波有便宜的独立公网 IP，但接入是电信单线，高峰期联通和移动用户延迟会明显上来。你的玩家如果主要是电信宽带，这条线没问题；玩家来源杂，还是回镇江或宿迁。

端口映射在雨云控制台的 NAT 端口映射页配置，协议选 TCP+UDP，外网端口默认随机分配，遇到提示“外网端口已被使用”就自己填一个，范围是 10000 到 60000。开一个 MC 服要映射三个端口：

- **23333**，MCSManager 网页面板
- **24444**，MCSManager 的 Daemon 守护进程
- **25565**，Minecraft 服务端默认端口

三條规则都建好，把 23333 对应的公网地址复制进浏览器，才能打开面板。

## 从零搭建的完整流程

**第 1 步，买机。** 控制台进云产品 → 游戏云 → 立即购买 → VPS 服务器，机型选 14900K，区域选江苏镇江，计费模式按上面的判断选，配置 4 核 8G 起，IP 类型保持默认 NAT。

**第 2 步，选系统。** 操作系统选 Debian 12，**软件安装不要勾选**。预装的宝塔、Docker 之类会占用端口和内存，开 MC 服不需要。

**第 3 步，配端口映射。** 按上一节把 23333、24444、25565 三个端口映射出去。

**第 4 步，SSH 登录。** 用 MobaXterm 或 PuTTY，主机填服务器公网 IP，端口填映射出去的那个 SSH 端口（独立 IP 机器一般是 22），用户名 root，密码在控制台可以看或重置。

**第 5 步，装 JDK。** 版本必须和服务端版本对得上：

| JDK 版本 | 对应 Minecraft 版本 |
| --- | --- |
| JDK 8 | 1.7 及以下 |
| JDK 11 | 1.8 ~ 1.16 |
| JDK 17 | 1.17 ~ 1.19 |
| JDK 21 | 1.20 及以上 |
| JDK 25 | MC 26 及以上 |

装错版本是最常见的启动失败原因。网上不少教程还在教 1.20 以后的服务端装 JDK 17，照做会直接报 `UnsupportedClassVersionError`。

**第 6 步，装 MCSManager。** 官方一键脚本要求 root 权限：

bash
sudo su -c "wget -qO- https://script.mcsmanager.com/setup_cn.sh | bash"


装完访问 `http://服务器IP:23333/` 设置管理员账号。也可以用 Docker 版脚本，装完会显示面板地址和一串 **Daemon 密钥**，多机管理时在“节点”里填远程 IP、24444 映射端口和这串密钥就能纳管。

**第 7 步，上传服务端 jar。** 在面板里新建实例，类型选 MC Java 版服务端，启动命令可以写成：


java -Xms1G -XX:MaxRAMPercentage=90.0 -XX:+UseZGC -Dfile.encoding=UTF-8 -jar server.jar nogui


`-Xms1G` 是初始堆内存，`-XX:MaxRAMPercentage=90.0` 限制 JVM 最多用到系统内存的 90%，`-XX:+UseZGC` 启用 ZGC 减少长时间运行的卡顿（JDK 15 以下要去掉这个参数），`-Dfile.encoding=UTF-8` 防中文乱码。

**第 8 步，过 EULA。** 第一次开启必然在控制台看到 `You need to agree to the EULA in order to run the server`。打开 `eula.txt`，把 `eula=false` 改成 `true`，保存后重启实例。

**第 9 步，开放容器端口。** 如果实例跑在 Docker 里，还要在“容器化 → 开放端口”里新增一条，主机端口和容器端口都填 25565，协议 TCP，否则外网连不进来。

**第 10 步，等 Done。** 控制台出现 `Done` 就说明服务端起来了。客户端进多人游戏 → 添加服务器，地址填 `公网IP:端口`，中间用英文冒号。NAT 机这里填的不是 25565，是 25565 映射出去的那个公网端口。

## 服务端选哪个

原版 `server.jar` 是 Mojang 官方程序，完全免费，不需要买什么“开服许可证”，但它装不了模组。

Paper 是 Spigot 的高性能分支，兼容大部分 Bukkit/Spigot 插件，单人服和十几个人的小服开 Paper 最稳，优化选项也多。

Fabric 轻量、跟进新版本快，追最新快照和模组的首选，但**必须先装 Fabric API**，否则其他模组一个都不生效。

Forge 模组生态最大，代价是高版本不能直接跑 jar。1.21 的 Forge 服务端要先用 `java -jar forge-1.21-51.0.23-installer.jar -installServer` 跑出安装结果，看到 `The server installed successfully` 后改 `user_jvm_args.txt` 里的 `-Xmx`，再把启动命令换成 `bash run.sh`。1.16.5 及以下才可以直接运行 jar。

Mohist 把 Forge 和 Bukkit 揉在一起，模组和插件能同时跑，但版本只更新到 1.20.2，想开 1.21 的服就别指望它了。

## 模组和换存档

模组分两类。客户端模组比如小地图，只装在本地就能用，服务端不需要。服务端模组比如连锁采集，必须服务端和客户端版本完全一致才生效，最稳的做法是本地和服务器各放一份相同的文件。

所有模组都扔进 `mods` 文件夹，没有就手动建一个。下载渠道要挑，来源不明的 mod 有被塞后门的风险，用 PCL2 这类启动器内置的下载功能更安全。

换存档有两种做法：把本地存档传上去覆盖 `world` 文件夹并保持同名，或者改 `server.properties` 里的 `level-name` 指向新的文件夹名。

换完之后启动失败，八成是文件属主问题。如果你建了普通用户（比如 `mcfabricuser`）来跑服务端，新上传的 world 目录属主还是 root，这个用户写不进去：

bash
sudo chown -R mcfabricuser:mcfabricuser /minecraft


还有一项 `online-mode` 要自己权衡。关掉正版验证，用第三方启动器的朋友能进来，代价是所有离线 ID 都能进，被 ban 了换个名字照样回来，公开服不要这么干。
